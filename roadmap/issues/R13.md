## 🎯 Objetivo

Definir e implementar DevOps, CI/CD, ambientes e secrets do WYD: dev, staging, prod; format + lint + testes; schema versionado; migrações explícitas; rollback documentado antes do go-live; secrets nunca no repo.

---

## 📦 Entregáveis

1. **Ambientes**: dev (código rodando local, banco de demonstração ou PG real via Docker), staging (validação com dump real ou fixture grande, aproxima produção sem expor produção), prod (servidor jogável com segurança, persistência, observabilidade).
2. **CI/CD**: format + lint + testes; schema versionado; migrações explícitas; rollback documentado antes do go-live.
3. **Secrets**: senha/hash/PIN, connection string de produção, chaves de API nunca no repo; no sistema do provedor (secret manager, Workers secrets, etc.); sem vazar no log.
4. **`out/` protegido**: `gitignore`; não compartilhar; não commitar; destruir após carga quando possível.

## 🧠 Riscos e limites

- **CI/CD**: format + lint + testes rodam no repo; schema versionado; migrações explícitas; rollback documentado antes do go-live.
- **Integração real com PG no CI**: opt-in via Docker; carga de dump real pode ser pesada e sensível, deixar para staging manual ou pipeline separado.
- **Release automático**: antes de ter um servidor jogável é prematuro.
- **Secrets**: senha/hash/PIN, connection string de produção, chaves de API nunca no repo; no sistema do provedor; sem vazar no log.
- **`out/` protegido**: `gitignore`; não compartilhar; não commitar; destruir após carga quando possível.
